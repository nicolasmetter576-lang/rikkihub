# 数据：备份、恢复、存储、日志、统计、升级

设置首页的“数据设置”分组：`设置 › 数据备份`、`设置 › 存储管理`、`设置 › 请求日志`、`设置 › Web服务器`。

## 备份到哪里

`设置 › 数据备份`：

- **文件**：「导出为文件」把设置和聊天记录存成一个文件；「导入本地备份文件」恢复。
- **WebDAV**：填 WebDAV 服务器地址、用户名、密码，「测试连接」后「立即备份」；文件列表里选一份恢复。
- **S3**：任何 S3 兼容的对象存储，填端点、区域、Bucket、访问密钥 ID、秘密访问密钥；「路径样式」打开时用 endpoint/bucket/object 形式。
- 「备份项目」：WebDAV 和 S3 备份可以选是否包含聊天记录（数据库）和文件（聊天附件等）。设置总是包含在内。
- 「备份提醒」：多久没备份就提醒一次。
- 「从其他APP导入」：从 ChatBox 导入提供商配置和完整聊天记录；从 Cherry Studio 导入提供商配置。

**注意：App 的备份不包含工作区里的文件**（包括作品模式的书稿和它的版本历史、回收站）。工作区要单独在它的「文件」页「导出 ZIP」。

## 备份加密

「备份加密」打开后，本地导出、WebDAV、S3 备份都用密码加密（文件扩展名 `.rkbackup`，不加密时是 `.zip`）。

- 「在本机记住密码」：密码只用系统密钥库保存在这台手机上，不会写进备份文件。
- **忘了密码就永远打不开加密备份，没有找回办法。**

## 本地快照（自动留底）

「快照」页：App 在前台空闲时定期在手机上保存数据库和设置的副本，防误删、防恢复出错。

- 「启用自动本地快照」、「自动拍照间隔」（默认按数据量自动调整）、「保留最近份数」、每周和每月各保留一份、「总容量软上限」。
- 「立即创建快照」；每份快照可以「置顶」（不会被自动清理）、「导出」、「恢复」。
- 剩余空间不足 512 MiB 时不拍快照。快照在手机本地，卸载 App 会一起删除，它不能代替导出到别处的备份。

## 恢复

1. 选备份后，App 先做「恢复前兼容性检查」：备份来自哪个版本、包含什么内容、有没有版本差异。版本差异较大时要勾选“我已了解版本差异，仍要继续恢复”。
2. 覆盖前会自动给当前数据拍一份“恢复前留底”快照。
3. 恢复需要重启 App 才能完成：点「关闭并安装」，App 关闭后再打开（没自动打开就手动打开）。
4. 重启后不满意，可以「撤销本次恢复」回到恢复前的状态。安装出错时会自动回滚，原有数据保留。

恢复会**覆盖**现有的设置和聊天记录（留底快照只保护聊天记录与设置，附件按路径写入）。

## 能不能装回旧版本

这是版本之间的规律，App 里没有专门的页面讲这个，回答时不要说成“某某页里写了”。

- 新版可以直接覆盖安装旧版，数据保留。
- **升级到较新的版本后，不能再装回旧版本**（新版可能升级了数据库结构，旧版打不开），旧版也恢复不了新版做的备份。升级前建议先在旧版里导出一份备份。
- rikkihub 和官方 RikkaHub 是不同的 App（包名不同），不能互相覆盖安装，数据不互通。

## 存储管理

`设置 › 存储管理`：查看聊天上传的图片、文件等占用，选择要永久删除的文件「清理文件」。删除不可撤销，被删的附件在对应聊天里就看不到了。

## 请求日志

`设置 › 请求日志`：打开「记录请求」后，记下每次请求的地址、请求头、正文和响应信息（状态码、错误）。排查“为什么报错 / 模型收到了什么”时最有用。Authorization、x-api-key 这类鉴权头和地址里的令牌参数在记录时就会遮掉（显示成 ██），但请求正文里可能有你的聊天内容，转发前留意。

## 统计

侧边栏底部「统计」：总对话数、消息数、输入输出 Token、缓存节省的 Token、聊天热力图，按模型和提供商的用量。估算花费要先在模型上填价格（见[第一次用](getting-started.md)）；还可以给提供商设消费上限。

## 安全模式

如果 App 上次启动时崩溃，下次打开会进入「安全模式」：可以「切换助手」（常见原因是某个助手的配置有问题），或「进入应用」照常启动，也能查看崩溃报告。
